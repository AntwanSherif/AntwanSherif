## What this is

Tailwind v4 / Motion v12 / pnpm). It renders the same `CVDocument` two ways:

## Conventions / gotchas (read before editing)

- A repo hook **blocks the `Write` tool on existing files** → use `Edit`, or `rm` then `Write`.
- **Dev server:** `pnpm dev` (runs `bin/dev`). The live port is in `.dev/port` at the repo
  root — read it, never hardcode (it's been `3130`). Never kill a process to free a port.
- The `cv.ts` data block is JSON (double-quoted keys) because the Save API regenerates it.
  Edit it via the `Edit` tool (between the sentinels) or via the `/cv/edit` page. Keep the
  sentinel comments intact.
- **Markdown in data:** `renderInline` parses `**bold**`, `*italic*`, `[text](url)`. In the
  editor these render as real formatting (not raw markers); the format bar uses
  `execCommand('bold'|'italic'|'createLink')` and serializes back to markdown.
- **Verify after edits:** `pnpm exec tsc --noEmit` (filter `data/cv` or `components/cv`),
  `pnpm exec eslint src/components/cv`, and `curl -s -o /dev/null -w '%{http_code}'
  http://localhost:<port>/cv`.
- Known benign lint: the editor's localStorage-hydration effect trips
  `react-hooks/set-state-in-effect` — it already has a scoped `eslint-disable`.
- The file is sometimes **edited live by the user** — if an `Edit` fails with "string not
  found" / "file modified", re-Read the target lines and retry.

## TASK 1 — Render the CV properly (kill the gray background)

**Symptom:** the public `/cv` shows the sheet floating on a "weird gray background."

**Cause:** `src/app/cv/page.tsx` wraps the document in:
```tsx
<div className="cv-stage min-h-screen bg-neutral-200/60 px-4 py-8 print:bg-white print:p-0">
```
`bg-neutral-200/60` was a design-exploration backdrop; it reads as unfinished.

**To decide / do:**
- Pick the screen treatment: pure white, OR a subtle premium neutral (e.g. `#f5f5f7`) with the
  sheet centered + its existing `box-shadow` (defined in `cv.css` `.cv-sheet`). A faint neutral
  + shadow usually looks more "document-like" than pure white; pure white is the safest.
- **Responsiveness:** `.cv-sheet` is a **fixed `210mm`** wide. On a phone it will overflow.
  For the *web* version, add responsive handling (e.g. `width: min(210mm, 100%)` on screen, keep
  `210mm` for print) so the page looks right on mobile. This is part of "render it properly."
- Keep all changes screen-only where possible; the `print:*` variants already handle print.
- Consider whether `/cv` should get its own minimal layout (no site nav/footer) — check
  `src/app/layout.tsx` to see what wraps it.

## TASK 2 — Print / 2-page optimization

**Current state:** page-break control **works** (no mid-block splits) — `cv.css` `@media print`
sets `break-inside: avoid` on `.cv-exp`, `.cv-side`, `.cv-proj`, `.cv-sheet li` and
`break-after: avoid` on `.cv-h`, plus `@page { size: A4; margin: 0 }` and
`print-color-adjust: exact` (preserves the blue header). BUT the content is now **~3 pages**
and **Education spills onto a near-empty page 3** (the thing to fix).

**Goal:** land a clean **2 pages**, or a *balanced* 3 — never 2-and-a-sliver. No orphan/near-
empty trailing page.

**How to inspect the actual PDF (do this first):**
```bash
B="$HOME/.claude/skills/gstack/browse/dist/browse"
PORT=$(cat ~/files/side-projects/portfolio/AntwanSherif/.dev/port)
$B goto "http://localhost:$PORT/cv"; $B wait .cv-sheet
$B pdf /tmp/cv-out.pdf
pdftoppm -png -r 80 /tmp/cv-out.pdf /tmp/cvpage   # → /tmp/cvpage-1.png, -2.png, ...
# then Read the PNGs to see where pages break
```

**Levers (print-only, in `cv.css @media print` — do NOT change the screen layout):**
1. Add small page margins via `@page { margin: 10mm 12mm }` and unset the sheet's own padding
   so content has room without feeling edge-to-edge.
2. Tighten vertical rhythm in print: reduce the main/sidebar `space-y`, section heading
   margins, and bullet `space-y` (these are Tailwind classes on the component — to make them
   print-only you may need print-scoped CSS overrides keyed off the existing class names, or
   add a `print:` Tailwind variant in the component).
3. Slightly reduce body font-size in print (e.g. scale the sheet down a hair) if needed.
4. Last resort — trim content (e.g. shorten a long bullet). **Confirm with the user before
   cutting any content; copy is considered locked.**

**Decision to get from the user:** firm 2-page target (may require minor trims) vs. accept a
balanced 3-page. Recommend trying 2 pages first via spacing only (no content cuts).
